# 发版流程

面向维护者。目标是让 **tag、`ctpapp.dproj` 里的版本号、APK 里的版本号** 三者始终一致，
避免"发了新版但用户装不上"这种最常见的翻车。

---

## 一键发版（推荐）

```bash
cd "Y:/DELPHI RAD11/delphictpapp"
./scripts/release.sh 1.1.0 "新增行情页；修复 xxxx"
```

脚本会依次做：

| 步骤 | 动作 |
|---|---|
| 1 | 检查工作区干净（有未提交改动直接中止） |
| 2 | 改 `ctpapp.dproj`：`versionCode` 自动 +1，`versionName` 设为 `1.1.0` |
| 3 | 提交这条版本号改动 |
| 4 | 打附注标签 `v1.1.0`，推送 `main` 与标签到 GitHub |
| 5 | 打印本地 APK 路径、MD5、APK 内实际版本号、Release 上传地址 |

剩下的只有一步手工：**把 APK 拖进 GitHub Release 页面**（附件走 HTTP API，`git push` 传不了）。

---

## 完整顺序

### 1. 编译前先想清楚这次是什么版本

| 改动性质 | 版本号 |
|---|---|
| 修 bug | 第三位 +1，如 `1.0.0` → `1.0.1` |
| 加功能、保持兼容 | 第二位 +1，如 `1.0.1` → `1.1.0` |
| 不兼容改动 / 大重构 | 第一位 +1，如 `1.1.0` → `2.0.0` |

`versionCode` 由脚本自增，**不需要手填**。它是安卓判断"是否升级"的唯一依据，
漏了递增会导致用户覆盖安装被系统拒绝（`INSTALL_FAILED_VERSION_DOWNGRADE`）。

### 2. 编译出 APK

RAD Studio → 目标平台 **Android 64-bit / Release** → Build。
产物：`Android64/Release/ctpapp/bin/ctpapp.apk`

### 3. 真机验证

必须走一遍：**启动 → 登录 → 报单 → 撤单 → 持仓查询**。
adb 连着的话可以顺便看崩溃：

```bash
adb logcat -b crash -d | tail -30
```

### 4. 跑发版脚本

```bash
./scripts/release.sh 1.0.1 "修复登录后闪崩"
```

### 5. 网页上传 APK

打开脚本打印的地址（形如）：

```
https://github.com/topview999/delphictpapp-v1/releases/new?tag=v1.0.1
```

- **Choose a tag** 选刚推上去的 `v1.0.1`
- **Release title** 填 `v1.0.1`
- **Describe** 写更新要点（可直接粘脚本里的说明）
- **Attach binaries** 拖入 `ctpapp.apk`，等进度条走完
- 点 **Publish release**

发布后的固定下载地址：

```
https://github.com/topview999/delphictpapp-v1/releases/download/v1.0.1/ctpapp.apk
```

## 手动发版（不用脚本）

```bash
cd "Y:/DELPHI RAD11/delphictpapp"

# ① 改版本号 —— 两处都要改（Android 与 Android64 配置，各一行）
#    ctpapp.dproj 里搜 versionCode=1;versionName=1.0.0
#    → versionCode=2;versionName=1.1.0

git add ctpapp.dproj
git commit -m "chore: 版本号升级至 v1.1.0"

# ② 打标签（-a 附注标签，务必带 -m）
git tag -a v1.1.0 -m "v1.1.0 更新要点"

# ③ 推送分支和标签（push 不会自动带标签）
git push origin HEAD
git push origin v1.1.0
```

然后回网页上传 APK。

## 常见坑

| 现象 | 原因 | 处理 |
|---|---|---|
| 用户覆盖安装失败 | `versionCode` 没递增 | 改大数字重新编译，重发 Release |
| tag 打到了错误的提交 | 在错误的分支/提交上执行 `git tag` | `git tag -d v1.1.0` + `git push origin :refs/tags/v1.1.0`，再在正确的提交上重打 |
| Release 已发布才发现 tag 错了 | Release 绑定在 tag 上 | 先在网页删掉该 Release，再删 tag 重打 |
| 上传 APK 时提示超过 2GB / 上传失败 | 附件上限 2GB，一般不会撞 | 检查网络；GitHub 附件支持断点续传，重试即可 |
| APK 里版本号和 tag 不一致 | 编译发生在改版本号之前 | 改完版本号后**重新编译**，再上传 |
| 下载链接 404 | Release 还是草稿，或附件未传完 | 网页上点 Publish release |

## 检查清单

发完版对照一遍：

- [ ] `git log` 里版本号提交存在
- [ ] `git ls-remote --tags origin` 能看到新标签
- [ ] Release 页面状态是 Published，不是 Draft
- [ ] 附件大小与本地 APK 一致
- [ ] 用手机从下载链接装一次，能覆盖旧版
- [ ] README 里的下载徽章指向 `releases/latest`（无需手改，自动跟随最新版）
